## 🎯 문제 정의

제주 원도심 칠성로 일대의 보행환경 조사에서:

- 기존 조사 방식은 전문 인력이 필요하고 시간·비용이 많이 소요됨
- 비전문가가 현장을 조사해도 **기준이 없어 데이터 품질이 낮음**
- 수집된 데이터를 행정에 전달할 **구조화된 체계가 없음**

→ **비전문가도 현장에서 즉시, 일관된 기준으로 보행환경을 조사할 수 있는 앱**이 필요하다

## 💡 디자인 의사결정

### 1. 지도 중심 UI
조사 데이터를 지도 위에 마커로 표시해 한눈에 현황을 파악할 수 있도록 설계.  
마커 색상을 위험도에 따라 🔴 상 / 🟠 중 / 🟢 하로 직관적으로 구분.

### 2. 네이버 지도 스타일 하단 카드
마커 탭 시 화면 하단에서 슬라이드업되는 상세 카드 채택.  
조사자가 지도 맥락을 유지하면서 상세 정보를 확인할 수 있도록 설계.

### 3. 조사 플로우 최소화
사진 촬영 → 카테고리 선택 → 위험도 선택 → 제출의 **3단계**로 조사 완료.  
비전문가도 현장에서 빠르고 일관되게 기록할 수 있도록 UX 흐름을 단순하게 유지.

### 4. 휠체어 불편지점 레이어
기존 조사 마커와 별도로 ♿ 버튼 하나로 휠체어 불편지점 35개를 토글.  
정보 과부하 없이 필요한 사용자만 레이어를 켤 수 있도록 설계.

## 📊 데이터 기반 인사이트

수집된 305건의 조사 데이터를 분석한 결과:

**조사 집중 패턴 발견**
- 전체 조사의 **38.1%(115건)**이 상위 5개 구역에 집중
- 문제가 고르게 퍼진 것이 아닌 **특정 구간에 몰림**을 데이터로 증명

**개선 1순위 구역 도출**
- 칠성로 상단 (칠성골 공영주차장 인근): 위험도 상 비율 **50%**
- 칠성로 중간 (탑볼링장 인근): 점자블록 파손 **4건 집중**
- 두 구역 합산 시 전체 위험도 상의 **25%**가 칠성로 한 거리에 밀집

→ 수치가 직접 가리키는 **현장 개선 우선순위**를 행정에 제시

## 🔄 데이터 관리 파이프라인

현장 데이터를 지속적으로 관리·수정할 수 있는 운영 체계 구축

```
Firebase (원본 데이터)
    ↓ export.py
엑셀 파일 (디자인 서식 적용 / 한글 컬럼명)
    ↓ 내용 검토 및 수정
    ↓ import.py
Firebase (업데이트 완료)
    ↓ download_images.py
조사 사진 로컬 저장
```
